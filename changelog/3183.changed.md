Change `JointType.ROD` from its four-entry layout of `SolverVBD` material slots to a seven-coordinate relative pose in `joint_q` and a six-DoF relative twist in `joint_qd`; use `joint_q_start` and `joint_qd_start` for state indexing. Rod stiffness and damping in `Model.joint_target_ke` and `Model.joint_target_kd`, which only the experimental `SolverVBD` reads, now use the material order `[shear_x, shear_y, stretch_z, bend_x, bend_y, twist_z]`. Migrate old material offsets `[stretch, shear, bend, twist]` from `[0, 1, 2, 3]` to `[2, (0, 1), (3, 4), 5]`. Code that indexed these arrays with `SolverVBD.JointSlot` must use the new offsets instead, because `JointSlot` remains the constraint-slot index for `SolverVBD.set_joint_constraint_mode()`. `eval_fk()` and `eval_ik()` now handle Rod state; constitutive dynamics remain `SolverVBD`-only.
