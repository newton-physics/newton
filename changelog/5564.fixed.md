Fix `SolverSteel` failing to compile its matrix-free sweep on CUDA when `free_body_constraint_max` exceeds about 12,000 rows per world ("uses too much shared data"); past that size the sweep keeps the free-body impulses in global memory. A shape whose dense rows and DOFs alone exceed the sweep's shared memory raises `ValueError` at construction. The CUDA free-body row metadata stores parent rows in 23 bits instead of 16, so friction rows whose contact row index is 32,768 or more are solved instead of skipped; `free_body_constraint_max` above 8,388,608 raises `ValueError` on CUDA.
