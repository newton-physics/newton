Fix `SolverMuJoCo` giving every world after the first the wrong `pair_gap`, `pair_margin`, `pair_friction`, `pair_solref`, `pair_solreffriction` and `pair_solimp` when `mujoco:pair_*` rows are authored once for a replicated scene. The kernel advanced through the rows by `row count // world count`, which assumes each world owns its own block; rows matching the template's pair count are shared by every world instead, so each world now reads the same row. Reads past the end of the row arrays are skipped rather than returning unrelated memory.
