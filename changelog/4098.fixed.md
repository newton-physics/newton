Advance stateful actuator state on the device so CUDA graph replay matches eager execution for any captured step count. `Actuator.step` published its update only into the caller's second state object, leaving the host-side `state_0, state_1 = state_1, state_0` swap to advance it; a captured graph replayed the recorded buffers instead, so an odd number of captured steps discarded the last step's update and a single captured step never advanced state at all. `Delay` rings, `ControllerPID` integrals and `ControllerNeuralLSTM` hidden and cell state were affected in both effort modes. The step now copies the advanced state back over the state it reads from, so both state objects hold it and the exchange is recorded in the graph. Keep passing two state objects to `Actuator.step`; the host-side swap is no longer needed and stays correct if kept.
