Size the body-pair reduction group table for the normal bins, voxels and depth layers that automatic coverage gives each body pair, so flush multi-collider stacks are less likely to fall back at the default `hashtable_size_factor`. The per-pair budget is a sizing heuristic, so fallback can still occur. With `cell_size=None` the table now requests up to 36 times more entries, capped at the staging capacity. Setting `hashtable_size_factor` to one over the per-pair fan-out (6 times the largest group's voxel count, for example 1/24 for box groups) keeps the table no larger than before, which can bring the fallback back; check `fallback_frames` in `CollisionPipeline.body_pair_reduction_stats()` and raise the factor when it is nonzero.
