Report the last solved force for contacts of sleeping `SolverSteel` islands whose rows are skipped (`sleep_skip_constraints=True`) in `CONTACT_F`, instead of zero. Across a collision pass the force follows contact matching, so it needs `contact_matching` enabled; a step on the unchanged contact set carries it without matching. Every solver step must request `CONTACT_F`; otherwise these contacts report zero until their island wakes. `sleep_skip_constraints=False` still solves and reports these forces directly. Code that treated a zero force on a sleeping body as asleep should read `SolverSteel.Observables.body_awake` instead.
