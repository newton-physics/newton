Report the last solved force for contacts of sleeping `SolverSteel` islands whose rows are skipped (`sleep_skip_constraints=True`) in `CONTACT_F`, instead of zero. The force carries only between consecutive solver steps that both request `CONTACT_F` on the same `Contacts` buffer, with the contact set either unchanged or produced by one collision pass with `contact_matching` enabled that matches to the solved set; a second collision pass between solver steps, a new `Contacts` buffer or a step without `CONTACT_F` drops these contacts to zero until their island wakes. `sleep_skip_constraints=False` still solves and reports these forces directly. Code that treated a zero force on a sleeping body as asleep should read `SolverSteel.Observables.body_awake` instead.
