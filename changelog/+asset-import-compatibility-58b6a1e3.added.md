Add per-import compatibility options for assets tuned with Newton 1.6, with migration guidance for the corrected Newton 1.7 interpretations:

  - **URDF joint damping:** Newton 1.7 maps `<dynamics damping="...">` to passive `joint_damping`; drive damping comes independently from `builder.default_joint_cfg.target_kd`. Use `builder.add_urdf(..., legacy_joint_damping=True)` to restore the authored per-joint drive damping, including distinct values and explicit zeros, while retaining the former passive-damping defaults. To migrate, leave the option disabled and configure controller drive gains explicitly; set per-joint `builder.joint_target_kd` values before `finalize()` when a common default cannot reproduce them. `SolverXPBD` and `SolverVBD` do not currently consume passive `joint_damping`, so applications using those solvers need the compatibility option or explicit drive damping to retain their former imported damping. Do not copy the authored coefficient into both fields to restore the old mapping: solvers consuming both would apply damping twice.
  - **USD joint-state angular velocities:** Newton 1.7 converts resolved `state:angular:physics:velocity` and rotational D6 `state:rot*:physics:velocity` values from degrees/s to radians/s, including revolute joints merged into D6 joints. For example, an authored value of `90` now initializes `joint_qd` to approximately `1.5708`. Use `builder.add_usd(..., legacy_angular_velocity_units=True)` to retain the previous unconverted values. To migrate, remove application code that manually converts the imported velocities. If an asset stored radians/s in these degree-based attributes to compensate for the old importer, multiply the authored values by `180 / pi` and disable the option. Rigid-body `physics:angularVelocity` conversion, joint positions, and linear velocities are unaffected; joint-state attributes still need to be recognized by the selected schema resolver.
  - **USD MuJoCo spring references:** Newton 1.7 interprets revolute `mjc:springref` according to the PhysicsScene's `mjc:compiler:angle`; an unauthored setting or absent PhysicsScene defaults to degrees. After `SolverMuJoCo.register_custom_attributes(builder)`, use `builder.add_usd(..., legacy_springref_units=True)` to preserve the former unconverted spring references, including those on revolute joints merged into D6 joints. To migrate an asset that stored radians under a degree compiler setting, multiply each affected revolute spring reference by `180 / pi`. Alternatively, author `mjc:compiler:angle = "radian"` only when all attributes governed by that setting, including `mjc:ref`, use radians. The compatibility option does not change `mjc:ref`, prismatic spring references, or MJCF import.

Leave these options disabled to use the corrected mappings. They affect only the asset loaded by that call, do not modify source assets or builder defaults, and do not restore all Newton 1.6 behavior. Compare the imported values and representative simulation trajectories before disabling each compatibility option.
