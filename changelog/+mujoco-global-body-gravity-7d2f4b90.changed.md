Reject different gravity for global world `-1` and world `0` in `SolverMuJoCo` when dynamic global bodies share one MuJoCo world with world `0` bodies: a MuJoCo world has one gravity, so construction now raises `ValueError` instead of applying the difference as an external force in `xfrc_applied`. To restore the previous motion when the global gravity is `s` times world `0`'s, set both to world `0`'s gravity with `Model.set_gravity()` and set each global body's gravity compensation to `mujoco:gravcomp = 1 - s * (1 - c)`, where `c` is its previous compensation (`0` by default); otherwise set both to the same value or move the global bodies into world `0`. A later change of only one of the two entries is not detected; such a MuJoCo world follows world `0`.
