# Isaac Sim 6.0.1 Newton Development Integration

## Goal

Use `little-veg/newton` as the editable Newton source tree for Isaac Sim 6.0.1 while preserving the stock Isaac Sim installation and keeping upstream synchronization straightforward.

Success means that a developer can edit Newton solver code in `/home/limx/github/newton`, launch Isaac Sim through a repository-owned command, and verify at runtime that Isaac Sim imported Newton from that checkout. The existing Newton GUI demo must still simulate rigid bodies on CUDA.

## Compatibility Baseline

Isaac Sim 6.0.1 bundles Newton 1.2.1, Warp `>=1.13,<1.14`, MuJoCo Warp 3.8.x, and MuJoCo 3.8.x. The fork's `main` branch is Newton 1.5 development code and requires newer dependencies, so it is not a safe drop-in replacement.

Development will therefore use branch `vegtsunami/isaacsim-6.0.1`, created from upstream tag `v1.2.1`. The fork's `main` branch remains available for tracking current upstream development.

## Repository and Remote Layout

- Checkout: `/home/limx/github/newton`
- `origin`: `https://github.com/little-veg/newton.git`
- `upstream`: `https://github.com/newton-physics/newton.git`
- Isaac-compatible branch: `vegtsunami/isaacsim-6.0.1`
- Isaac Sim installation: `/home/limx/apps/isaacsim-6.0.1`

Solver development belongs in the fork. Isaac Sim-specific launch and verification helpers also belong in the fork so that the development workflow is versioned and reproducible.

## Integration Design

A repository-owned launcher will prepend the checkout to `PYTHONPATH` and then invoke the stock `isaac-sim.newton.sh`. It will not replace, delete, or symlink files inside the Isaac Sim installation.

Before starting Isaac Sim, the launcher will validate that the expected installation and source package exist. During startup, a small verification script will print the following information:

- `newton.__file__`
- `newton.__version__`
- active Isaac Sim physics engine
- Warp device

Startup must fail clearly if `newton.__file__` does not resolve beneath `/home/limx/github/newton`. This prevents silently testing the bundled package after changing fork code.

The launcher will accept additional Isaac Sim arguments so it can run the full GUI, an `--exec` demo, or future test scripts through the same environment.

## Runtime Data Flow

```text
Isaac Sim USD stage
  -> isaacsim.physics.newton integration extension
  -> Newton model/state/contact conversion
  -> Newton solver from /home/limx/github/newton
  -> Warp CUDA kernels
  -> Fabric transforms
  -> Isaac Sim GUI viewport
```

Initial work will retain Isaac Sim's supported `SolverMuJoCo` or `SolverXPBD` selection. A future custom solver can be added behind `SolverBase`, followed by a focused change to the Isaac integration's solver factory.

## Failure Handling and Rollback

The launcher will report actionable errors for a missing Isaac Sim installation, missing Newton checkout, incompatible import path, or failed runtime import.

Rollback requires no package restoration: launch `/home/limx/apps/isaacsim-6.0.1/isaac-sim.newton.sh` directly to use the bundled Newton package. Removing the repository-owned launcher has no effect on the Isaac Sim installation.

If `PYTHONPATH` precedence is changed by a future Isaac Sim update, implementation must stop rather than modify the installed prebundle. A repository-owned Kit extension or startup bootstrap may then enforce source precedence without overwriting installation files.

## Verification

Verification will cover four layers:

1. Repository: branch, remotes, clean status, and Newton version match the 1.2.1 compatibility baseline.
2. Import: the Isaac Sim Python runtime resolves `newton.__file__` inside the fork.
3. Solver: the active engine is `newton`, the CUDA device is available, and Warp kernels compile or load from cache.
4. End-to-end GUI: the existing lit rigid-body demo opens in Isaac Sim and advances without Python exceptions.

Automated helper tests will use `unittest` in accordance with the repository rules. Any test introduced for source-selection behavior must be observed failing before its implementation is added.

## Non-goals

- Upgrading Isaac Sim 6.0.1 to the fork's Newton 1.5 development dependencies.
- Modifying or replacing files in Isaac Sim's `pip_prebundle` directory.
- Implementing the custom rigid-body/articulation solver in this setup change.
- Changing the public Newton API before the solver design is specified separately.
